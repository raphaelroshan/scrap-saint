# Task packet: P17.1 — Confluence exploration

## Player-facing objective

Define how two committed Rank III weapons can become one unmistakably new machine while preserving understandable recipes, viable separate weapons, and the current four-slot build economy.

## Authority and command boundary

This is a design-only task. Existing content and `game/simulation.gd` remain authoritative; no Confluence command or content entry is enabled. Future implementation would place eligibility, source consumption, result creation, targeting, damage, statuses, save state, and replay traces in the deterministic simulation. Presentation would render only the returned transformation and attack events.

## Preserved contracts and non-goals

- Preserve ten enabled weapons, ten catalyst Evolutions, seven Gifts, four Blessings, four active slots, one reserve, two currencies, and current save/replay behaviour.
- Keep Vows and Boss Imprints explicitly `WIP / DESIGN ONLY` as alternative ways to satisfy an Evolution proof.
- Keep Confluence distinct from Combine and Evolution: two different active Rank III base weapons become one named hybrid.
- Do not enable a Confluence, add a currency, alter shop odds, change balance, or claim acquisition feasibility.
- Do not allow Evolutions as initial Confluence ingredients, triple merges, hidden recipes, or boss-required hybrids.

## Acceptance checks

1. Catalyst, Vow, and Boss Imprint Evolution paths have distinct acquisition purposes and share one Rank III/altar boundary.
2. The Confluence contract defines eligibility, atomic mutation, source lineage, slot result, preview, Gifts, saves, Results, and stable rejection reasons.
3. At least four current-roster pairs have new geometry, a primary question, a weakness, and four-beat animation direction.
4. The first proposed packet contains only The Line That Rings and Procession Harness.
5. Redundant or over-broad pairings are explicitly rejected rather than retained as catalogue filler.
6. The document identifies economy feasibility, human readability, and overlap as unproven gates.
7. Content validation and repository diff checks remain green.
