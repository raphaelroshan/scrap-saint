# Uncoached Workshop acceptance session

Status: NOT RUN. This is an observation worksheet, not evidence of acceptance.

Use the delivered Windows preview at normal 1x speed. Record package SHA-256, source revision, date, viewport, input device, participant experience and whether the profile is new. Do not delete an existing player profile to run this session. Use a separate Windows test account or an isolated test-data environment if a fresh profile is needed.

Give one goal: “Start a pilgrimage and try to finish the Collapsed Workshop. Use the game’s own help whenever you want.” Do not prescribe repairs, a weapon, an Evolution or a route. The observer may answer equipment/setup questions but should record any gameplay coaching and mark that observation as coached.

| Moment | Record actual observation and timestamp |
| --- | --- |
| Title and setup | Can the player start, identify their frame/Blessing and enter combat? |
| Opening combat | What does the player believe advances the run? Can they move and recognize automatic attacks? |
| Optional work | Do they understand the benefit, retained progress, healing deferral and ability to ignore repairs? |
| First shop | Which item do they choose, why, and what change do they expect next wave? Can they leave the shop? |
| Pause/help | Can they find help, return to the same paused state and resume? |
| Memory Crane / Foreman | Which body is the threat, what does its warning predict, and what caused damage? |
| Save and Continue | Can they leave at a safe boundary and resume without losing the intended run? |
| Defeat or Workshop clear | Can they explain the result and find retry or onward travel without help? |

After the attempt, ask what they were trying to achieve, which purchase mattered, whether repairs were required and what they would change next run. Record their own words rather than rating their answer against the observer's preferred build.

Pass only when progression, optionality, one build decision and recovery are understood without gameplay coaching. List each failure with a timestamp, expected behavior, observed behavior and smallest proposed correction. Record enjoyment/replay interest separately from technical correctness. A death alone is not an acceptance failure.

Do not expand to additional content while an observed main-path failure remains. Choose exactly one demonstrated issue for the next implementation packet after the session.
